# PhotoMark 照片水印工具

一个完全离线的桌面照片水印工具。支持 macOS Apple 芯片和 Windows x86-64。当前版本 v0.1.3 实现目录选择、日期与地点水印、四角位置、预览、批量处理和断点续处理；地点默认自动提取，主界面使用无需滚动的分栏与页签布局。

## 直接运行

`release/` 中的文件不需要安装 Node.js：

**直接使用：[下载最新 Release](https://github.com/henudev/photomark/releases/latest)**，在页面下方的 **Assets** 选择对应系统的成品。

代码仓库不提交应用安装包、开发依赖和本地测试输出；安装包作为 Release 附件分发。也可以按下方“本地开发与打包”在本地生成 `release/` 目录。

| 平台 | 交付文件 | 使用方法 |
| --- | --- | --- |
| macOS Apple 芯片 | `PhotoMark-0.1.3-mac-arm64.zip` | 解压，将 `PhotoMark.app` 拖到“应用程序”，双击运行 |
| Windows x86-64 | `PhotoMark-0.1.3-windows-x64.exe` | 便携版，双击运行；无需安装环境 |

文件用途、开发目录和清理建议见 [产物说明](产物说明.md)。旧版文件归档在 `release/history/`；日常使用只需 `release/` 顶层的当前成品。

当前构建未使用开发者证书签名或 Apple 公证。macOS 首次打开如果被系统拦截，在“系统设置 → 隐私与安全性”中选择“仍要打开”；Windows 可能提示未知发布者。面向公众正式发行时，应使用自己的证书签名，并在 macOS 上公证。

开发机为 macOS ARM64。照片处理功能已通过 17 项核心测试、实际 Electron 窗口操作检查、地点自动提取与补充检查，以及三种窗口尺寸下四个设置页签的完整可见性检查。Apple 芯片打包应用原生运行，成功预览并批量导出 6 张照片。Windows EXE 已打包并核对二进制架构、原生依赖和打包源码一致性，但没有 Windows 真机运行结果。本地检查结果保存于 `verification/ui-report.json`、`verification/location-ui-report.json`、`verification/format-ui-report.json` 与 `verification/release-report.json`；它们不提交到代码仓库，可运行相应检查脚本重新生成。

## 使用步骤

1. 选择存放照片的源目录，按需勾选“包含子文件夹”。
2. 输出目录默认为源目录旁边的 `原目录_水印`。支持更改；源目录与输出目录不可相同或相互包含。
3. 左侧通过“日期、地点、样式、导出”四个页签切换设置。主界面与设置区域无需滚动，预览及批处理操作始终可见。
   - 地点默认“自动提取地点（EXIF 优先）”。未提取到时显示小提示及手动补充输入框；不填写则省略地点。
   - 手动补充只用于本批没有自动位置信息的照片；有位置的照片保留各自位置。需要全部统一时选择“全部使用手动地点”。
4. 逐张查看右侧预览。“查看原图”用于对照，“放大预览”可切换 1:1 原始分辨率查看。
5. 在“开始批量处理”按钮旁选择 **PNG / JPG**；也可以在“导出”页签点击对应格式卡片，两个入口同步且自动记住选择。点击“开始批量处理”。暂停会等当前照片处理完成，再保存进度。
6. 重启后点击“恢复上次任务设置”，再开始处理；也可重新选择同一源目录、同一输出目录和同一组设置。程序会核对进度，只处理未完成或缺失的结果。
7. 失败项目单独列出，可导出 CSV。修复原因后再次运行，成功项目不会重复生成。

## “不影响画质”的准确范围

- 原照片始终保留，不覆盖、不缩放、不裁切、不自动调色。
- 新任务提供 **PNG** 和 **JPG** 两种导出选项，默认 PNG 无损压缩。无损指合成后的图像不会再被有损压缩。添加水印本身必然修改覆盖区域，不能保证整个文件或所有像素都与原图相同。
- 格式选择会自动保存，两个入口保持同步；处理期间锁定格式。PNG / JPG 使用独立任务记录，切换格式不会覆盖已有成品。旧版 TIFF 设置和任务仍可恢复，常规新任务仅显示 PNG / JPG。
- 对支持的 8 位 RGB 图像，处理时忽略自动 ICC 转换，直接在原编码 RGB 数值上合成，并保留原 ICC 配置。自动处理 EXIF 方向；方向校正可能交换宽高，但不裁切或改变像素数量。
- 自动测试检查了普通 PNG、JPEG 解码后转 PNG、透明 PNG 和 P3 ICC 样本中未覆盖区域的像素一致性。这些结果不代表覆盖了所有相机和色彩配置；专业工作流请先用自己的样本验收。
- **JPEG 质量 100、4:4:4 仍然需要重新编码，属于有损输出。** 对画质要求严格时选择 PNG，代价是体积增加。
- 预览与导出共用水印合成过程；常规预览缩小至最多 1440 × 1080，放大预览使用原始分辨率。导出保持原始分辨率。
- ICC 色彩配置始终保留。可取消保留 EXIF 等拍摄元数据，以减少 GPS 等隐私信息；如果 GPS 已经作为可见水印写入画面，取消保留元数据不会移除画面中的文字。

## 日期和地点

| 设置 | 行为 |
| --- | --- |
| 拍摄时间优先 | EXIF `DateTimeOriginal` / `CreateDate` → 文件名时间 → 文件修改时间 |
| 文件名时间优先 | 文件名时间 → EXIF 拍摄时间 → 文件修改时间 |
| 文件修改时间 | 使用操作系统文件修改时间，不自动回退 |
| 手动指定 | 所有照片使用指定时间，精确到秒 |
| 不显示日期 | 仅添加地点；地点也关闭时会提示水印为空 |

EXIF 保持相机记录的本地时间，不强制转换时区。文件修改时间按运行电脑的本地时区显示；复制文件可能改变其修改时间。发生时间回退时，预览明确显示实际来源。

文件名例子：`IMG_20261109_143025.jpg`、`2026-11-09_14-30-25.png`、`20261109.jpg`。没有时分秒时补 `00:00:00`。

支持预设或自定义日期格式，例如 `yyyy年MM月dd日 HH:mm:ss`。支持的字段为：年 `yyyy`、月 `MM`、日 `dd`、时 `HH`、分 `mm`、秒 `ss`，注意大小写。

自动地点的读取顺序：**EXIF 地点名称 `GPSAreaInformation` → 照片内嵌 XMP/IPTC 拍摄地点名称（如城市、具体地点）→ EXIF GPS 经纬度 → 手动补充 → 省略地点**。不会从照片说明、文件名或画面内容猜测地点，也不会把画面主体的 `LocationShown` 当作拍摄地点。

自动读取失败时，显示“未提取到位置信息，可在下方手动输入”，并出现输入框。每张照片独立判断；手动补充应用于本批所有未提取到位置的照片，不覆盖其他照片的自动地点。切换回有 GPS 的照片时，输入框收起并显示提取来源。批处理结束后汇总缺失、手动补充和省略数量。

**本版不联网将 GPS 转成城市、地址**。照片只有 GPS 时，自动显示经纬度；要统一显示自己填写的地名，可选择“全部使用手动地点”。仍保留“仅显示 EXIF GPS 坐标”和“不显示地点”选项。

升级 v0.1.0 时，当前地点偏好会调整为自动优先，之前填写的文字保留为缺失时的补充；显式“不显示地点”保持不变。“上次任务”的原设置保留，恢复旧任务时仍使用其原有设置，以保证断点记录可继续匹配。

四个角都可选，长文本会自动缩小以避免横向越界。中英文字体随程序打包，两个系统均不依赖用户另外安装字体。

## 无滚动主界面

源目录与输出目录并排显示，设置拆分为“日期、地点、样式、导出”，预览区域随窗口高度伸缩；主界面没有纵向或横向滚动条。已检查内容区域 1040 × 708、1350 × 860 和 1440 × 980 三种尺寸，包括手动日期、自定义格式、地点缺失提示展开时，各控件完整可见。桌面窗口最小尺寸保持 1040 × 740（包含系统标题栏）。

1:1 原图查看时允许平移查看超出窗口的图像；失败清单在独立弹窗中查看，长清单可滚动，不改变主界面布局。长路径和提示使用省略显示，鼠标悬停可查看全文。

## 格式支持

- 支持输入：JPG / JPEG、PNG、静态 WebP、单页 8 位 TIFF。
- 不支持输入：HEIC / HEIF、相机 RAW / DNG、高位深 16 位图像、CMYK / Lab、多页 TIFF 或动画图像。这些文件不会被悄悄降位深；扫描提示 HEIC / RAW 数量，其余不支持项在预览或批任务中记录具体错误。
- HEIC / RAW 需要先用系统照片工具或相机软件导出 RGB 照片。若要直接处理 HEIC、HDR、16 位 RAW，需要后续增加解码和高位深合成实现。
- 当前不包含参考图里的品牌边框、冲印尺寸、照片挑选模块；这些不属于本次列出的五项核心需求。

## 断点记录与文件安全

目标目录包含隐藏的 `.photomark/task-任务编号.json`，保存设置、源图 SHA-256、输出 SHA-256、状态和错误；每完成一张都会更新并同步到磁盘。请保留该目录才能继续原任务。

输出例子：`IMG_20261109_143025.jpg.watermark-a1b2c3d4.png`。保留原始扩展名可避免同名 JPG / PNG 冲突；短编号对应这组源目录及水印设置，更换设置会生成独立结果。子文件夹结构会保留。

- 恢复时核对原图和完成文件的哈希，已确认完成的照片跳过。
- 已完成的输出被删除时会补做。源图或已完成输出被修改时，不覆盖现有内容，提示更换输出目录重新处理。
- 写文件先在同目录生成临时文件，再排他发布。普通本地文件系统使用硬链接；exFAT 或不支持硬链接的磁盘回退到排他复制。
- 硬中断发生在“写出后、完成记账前”时，恢复可认领内容一致的结果。exFAT 复制中断产生的部分文件会保留为 `.interrupted-唯一编号`，随后补做。
- 失败项目不阻塞其他照片。处理采用单张串行队列，以限制大图批处理的内存占用；支持子目录，但不遍历符号链接。
- 关闭窗口时等待当前图像完成并保存。强制结束进程后，下次运行依靠目标目录的记录恢复。
- 记录损坏、磁盘权限不足或磁盘空间不足会提示具体错误，不会把它们当作成功。

该机制提供进程中断恢复，不保证任何硬盘断电、损坏或网络存储故障下的绝对持久性。大型照片库建议先用一个小目录验收。

## 本地开发与打包

建议 Node.js 22 或更新版本。源码不需要在线服务，首次安装依赖和下载打包工具需要网络。

```sh
git clone https://github.com/henudev/photomark.git
cd photomark
npm ci
npm start
```

生成离线演示照片（程序生成的测试图，并非真实拍摄）：

```sh
npm run demo
npm start -- --demo
```

测试与构建：

```sh
npm test
npm run test:ui
npm run test:location-ui
npm run test:format-ui
npm run build:mac
npm run build:win
```

macOS 构建仅生成 Apple 芯片 arm64 ZIP；Windows 构建生成 x86-64 便携 EXE。本项目使用 Electron + sharp 预编译依赖，macOS 上的打包前置脚本会显式准备 Apple 芯片 Mac 与 Windows x64 所需模块。`signAndEditExecutable: false` 允许当前无 Wine 环境生成 Windows 便携包，应用内层 EXE 的图标 / 发布者资源仍为 Electron 默认值；正式签名发行应在 Windows 上配置资源编辑与签名。

`.github/workflows/build.yml` 在 Apple 芯片 Mac 和 Windows x64 上分别执行核心测试与打包。Actions 页面手动运行时仅构建临时产物；推送 `v*` 版本标签时，两平台成功后自动创建 GitHub Release，上传两个成品、使用说明、产物说明和 SHA-256 校验文件，再公开发布。普通代码推送不会自动触发构建。

### 发布到 GitHub Release

Release Notes 是页面上的版本说明；真正可下载的安装包放在该页面的 Assets 中，源码 ZIP / tar.gz 由 GitHub 根据版本标签自动提供。

发布新版本时：

1. 更新 `package.json` 与 `package-lock.json` 的版本号，更新文档中的版本与下载文件名。
2. 新建对应说明，例如 `release-notes/v0.1.4.md`。
3. 提交并推送代码，再推送相同版本标签：

```sh
git push origin main
git tag v0.1.4
git push origin v0.1.4
```

标签必须等于 `v` 加 `package.json` 版本号；不一致或缺少版本说明时构建会停止。工作流会先上传草稿附件，确认完整后再发布；不覆盖已公开版本。失败后可在 Actions 重跑对应工作流，未完成草稿可以继续上传。

Release 附件使用通用英文文件名：`README-zh-CN.md` 为中文使用说明，`ARTIFACTS-zh-CN.md` 为中文产物说明，避免平台规范化中文附件名时发生冲突。

若两个平台已经构建成功、仅发布步骤失败，可在 Actions 手动运行工作流，填写 `release_tag` 和原构建的 `artifact_run_id`。工作流会核对产物提交与版本标签一致、两个构建任务均成功，然后复用产物完成发布。

## 源码结构

```text
src/main.cjs          Electron 窗口、目录对话框、IPC、任务协调
src/preload.cjs       隔离的前端桥接接口
src/image.cjs         图像检查、方向校正、字体路径、水印合成和导出
src/time.cjs          EXIF / 文件名 / 文件时间解析与格式化
src/location.cjs      自动地点提取、GPS 校验与缺失时手动补充
src/batch.cjs         批队列、SHA 校验、任务日志、排他输出、恢复
src/settings.cjs      设置默认值和校验
src/storage.cjs       JSON 原子替换和同步写入
renderer/            中文桌面界面、设置与预览
assets/              应用图标与 Noto Sans CJK 字体、字体许可证
test/                核心行为测试
scripts/             演示图、界面测试、跨架构依赖准备
verification/        界面截图、运行测试报告、构建核对记录
release/             可运行应用与压缩包
```
